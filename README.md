# wxsec · 微信小程序安全测试工具

> **wxsec is intended for authorized security testing and education only.**
> **Do not use it against applications you do not own or have written permission to test.**
> **The authors accept no liability for misuse.**

wxsec 是一个 Windows 桌面工具（Go + [Wails](https://wails.io) v2），把「定位本机小程序包 → 解密解包 → 还原页面结构 → 静态安全扫描 → 接口资产梳理 → 导出报告」串成一条可复现的测试流水线，用于**对自己拥有或已获书面授权的小程序**做安全自查与学习研究。

界面为简体中文，单文件免安装，无云端上传，所有解析与扫描都在本机完成。

## 能做什么

| 能力 | 说明 |
| --- | --- |
| **包发现** | 自动探测 PC 微信（4.x `xwechat/radium` 布局）与旧版微信的小程序缓存根目录，按 `AppID/版本/文件` 聚合列出本机已下载的小程序包 |
| **解密解包** | 识别 `V1MMWX` 加密包头，按 AppID 派生密钥解密，解析包索引并落盘还原文件树；支持直接选择任意 `.wxapkg` 文件 |
| **WXML / WXSS 还原** | 用 [goja](https://github.com/dop251/goja) 直接执行包内编译产物（`page-frame`、`appservice.js` 等），把渲染函数产出的虚拟 DOM 反推为 WXML，并从 `setCssToHead` 抽取 WXSS。绑定表达式用哨兵值保留 `{{}}`、`wx:if`、`wx:for` 原样 |
| **静态安全扫描** | 21 条内置规则覆盖硬编码密钥、敏感个人信息、接口与资产、危险用法四类；命中带文件、行号、上下文与处置建议 |
| **接口资产梳理** | 提取全部 URL 并归并去重；内置厂商域名表，把第三方 SDK / 公共 CDN / 许可证注释里的 URL 与目标自有资产分流，避免资产面虚高 |
| **报告导出** | 一键生成自包含 HTML 报告与 JSON 结果，含摘要卡、命中清单、资产清单与复现参数 |
| **代码浏览** | 树形浏览解包目录并查看源码，扫描结果可一键「定位」到对应文件行 |
| **缓存管理** | 按 AppID 查看并清除本机小程序缓存（支持全选/批量），便于让微信重新下载包以复测；删除边界校验全部在后端完成 |

## 快速开始

1. 到 [Releases](../../releases) 下载 `wxsec-v0.1.0-portable-win-x64.zip`。
2. 解压得到 `wxsec/` 文件夹，双击 `wxsec.exe`（免安装、无需管理员权限）。
3. 若启动后界面空白，说明缺少 WebView2 运行时，安装 [WebView2 常青版运行时](https://learn.microsoft.com/microsoft-edge/webview2/) 后重试（Win10 1803+ / Win11 一般已内置）。

首次使用请先在 PC 微信中打开目标小程序，让客户端把包下载到本机缓存，再回到工具里点「自动探测微信缓存目录 → 枚举小程序包」。

## 从源码构建

依赖：Go 1.24+、Node.js 18+、Wails CLI v2。

```bash
go install github.com/wailsapp/wails/v2/cmd/wails@latest

cd wxsec
wails build -clean -ldflags="-w -s"     # 产物：build/bin/wxsec.exe
go test ./...                           # 单元测试
```

国内网络建议先设置代理镜像：

```bash
go env -w GOPROXY=https://goproxy.cn,direct
```

`wails build` 会先执行 `frontend/` 的 Vite 构建，再通过 `//go:embed` 把前端打进单个 GUI 子系统可执行体（`-H windowsgui`，双击不弹控制台）。

## 典型使用流程

1. **包发现** — 探测缓存目录 → 枚举包 → 勾选目标。
2. **解包任务** — 设定输出目录，勾选「代码美化 / 还原 WXML、WXSS / 解包后自动扫描」→ 解包选中。任务面板显示阶段进度。
3. **安全扫描** — 对解包目录执行扫描，按等级与关键字筛选命中项，点「定位」跳到源码。
4. **接口资产** — 查看目标自有 URL 与域名清单，按需开关第三方 SDK 过滤。
5. **报告导出** — 生成 HTML / JSON 报告并打开所在目录。

## 输出位置与隐私

| 内容 | 位置 |
| --- | --- |
| 解包产物 | `~/wxsec-output/<包名>_unpacked/`（可在界面改） |
| WXML/WXSS 还原产物 | 上述目录内的 `_decompiled/` 子目录，**不覆盖原始解包文件** |
| HTML / JSON 报告 | `~/wxsec-reports/` |

隐私约束（代码层面强制，不依赖使用者自觉）：

- 密钥类命中在界面与报告中一律**掩码**显示，不输出明文。
- 所有写入路径都经目录前缀校验，包内条目名经 `sanitizeEntry` 处理，阻断 `../` 目录穿越。
- 缓存删除只允许作用于「所选缓存根目录下、目录名等于合法 AppID、且确实装有 `.wxapkg`」的目录，符号链接跳过，且必须二次确认。
- 工具不联网上传任何数据；解包内容留在本机。

## 项目结构

```
wxsec/
├── app.go                    # Wails 绑定层：任务、进度聚合、各阶段编排
├── main.go                   # 窗口与生命周期
├── internal/
│   ├── wxapkg/               # 包格式解析、V1MMWX 解密、解包、代码美化
│   ├── decomp/               # goja 执行编译产物，还原 WXML / WXSS
│   ├── scanner/              # 规则引擎、资产提取、第三方 SDK 域名分类
│   ├── report/               # 自包含 HTML / JSON 报告
│   ├── wechat/               # 缓存目录探测、包枚举、缓存清除
│   ├── proxy/                # （开发中）本地 MITM 抓包代理与系统代理接管
│   └── cross/                # （开发中）动态流量与静态资产的 URL 对照
└── frontend/                 # 原生 JS + Vite 界面（无框架依赖）
```

## 静态扫描规则

| 分类 | 规则 |
| --- | --- |
| 硬编码密钥 | `KEY-001` AppSecret/SecretKey、`KEY-002` apikey/token/password、`KEY-003` 阿里云 AK、`KEY-004` AWS AK、`KEY-005` JWT、`KEY-006` 私钥内容、`KEY-007` 商户号/对称密钥 |
| 敏感个人信息 | `PII-001` 手机号、`PII-002` 身份证（校验位）、`PII-003` 银行卡（Luhn）、`PII-004` 邮箱 |
| 接口与资产 | `NET-001` 明文 HTTP、`NET-002` 硬编码 IP、`NET-003` 内网/保留地址、`NET-004` 隧道/临时回调域名 |
| 危险用法与配置 | `DGR-001` 动态代码执行、`DGR-002` web-view 加载、`DGR-003` 重定向参数、`DGR-004` 本地存储身份数据、`DGR-005` 调试开关/测试环境残留 |

静态扫描产出的是**待验证线索**，不是结论：命中需要人工结合接口实际行为确认，误报（如示例数据、第三方库自带常量）属正常现象。

## 已知限制

- **还原不是源码还原**：产物是编译后模板的反推结果，属性顺序、组件别名与 `wx:` 指令细节与原始 WXML 不完全一致，也不能回编译。
- **JS 引擎限制**：个别包的 `app-service.js` 含 goja 无法解析的现代语法，该包会被跳过并记入跳过清单（模板仍可能由 `page-frame` 提供）。
- WXSS 还原依赖 `setCssToHead` 的常见实现形式，遇到非标准封装会取不到样式。
- 仅支持 PC 微信本机缓存中的包；不会绕过服务端鉴权，也不提供接口爆破、批量扫描等服务端测试能力。
- 平台以 Windows 为主，其他系统未做适配验证。

## 开发中

`internal/proxy` 与 `internal/cross` 已入库（MITM 抓包代理、按域名签发证书、系统代理接管与恢复、动态/静态 URL 对照），但**尚未接入界面**，当前发行版不包含抓包功能。后续计划：抓包面板与实时流量表、抓包与静态资产的交叉视图、URL 清单导出 Excel。
